Qué vas a aprender

Esta práctica te enfrenta al primer componente real del restaurante HANA. Antes de escribir una sola línea de CSS, leerás la maqueta, identificarás las capas del modelo de caja de cada elemento y razonarás qué hace el navegador por defecto cuando coloca esas etiquetas. Al terminar sabrás controlar dimensiones, espaciados, bordes y sombras con precisión, y tendrás la base sobre la que construiremos todos los componentes siguientes.

Situación

El restaurante HANA te ha contratado como desarrollador frontend freelance. Lo primero que te piden es la card de plato que aparecerá en la sección del menú online. El diseñador ya tiene la maqueta lista en el sistema de diseño. Tu tarea es traducirla a HTML y CSS limpio, siguiendo los tokens del sistema, sin usar Flexbox todavía: solo el flujo normal del documento y el modelo de caja.

Pasos

  1. Crea el archivo CSS y copia los tokens

    Abre el navegador con el HTML antes de escribir nada. Observa lo que el navegador aplica por defecto: los elementos se apilan uno debajo del otro, cada bloque ocupa todo el ancho, hay márgenes entre párrafos y encabezados que no has definido. Eso es el CSS de agente de usuario — la capa base que el navegador añade siempre. El reset que vas a escribir la borra para partir de cero.

    Tu tarea
    1. Crea el archivo css/style.css.
    2. Escribe el reset universal (*, *::before, *::after) con box-sizing: border-box, margin: 0 y padding: 0.
    3. Añade la regla defensiva para imágenes: max-width: 100%, height: auto y display: block.
    4. Crea el bloque :root { } y pega dentro el bloque completo de tokens de la guía de estilos de HANA.
    5. Guarda, recarga el navegador y comprueba que los márgenes por defecto han desaparecido.
    /* css/style.css */ /* 1. Reset: borramos los márgenes y paddings por defecto del navegador y hacemos que el modelo de caja incluya el borde en el ancho total */ *, *::before, *::after { box-sizing: border-box; margin: 0; padding: 0; } /* 2. Regla defensiva para imágenes — explica el paso 3 */ img { max-width: 100%; height: auto; display: block; } /* 3. Variables del sistema de diseño */ :root { /* ← pega aquí el bloque completo de la guía de estilos de HANA */ }
    🔍
    ¿Por qué display: block en las imágenes? Por defecto <img> es inline, igual que una letra dentro de un párrafo. El navegador reserva un pequeño espacio debajo para los descendentes tipográficos (como la parte de abajo de la «g» o la «p»), aunque la imagen no sea texto. Ese espacio aparece como un hueco inexplicable bajo la imagen. Compruébalo ahora: quita display: block y mira el hueco que aparece entre la imagen y el cuerpo de la card.
  2. Limita el ancho de la card y céntrala

    La card ocupa todo el ancho de la ventana porque <article> es un elemento de bloque: el navegador lo estira hasta llenar su contenedor por defecto. Si pones width: 300px, prueba a estrechar la ventana — la card se saldrá porque width fija el ancho exacto sin adaptarse. Lo que necesitas es una propiedad que establezca un límite máximo pero que permita que la card sea más estrecha si el espacio no llega a 300px. Con solo esa propiedad, la card sigue ocupando el 100% del padre hasta llegar a ese techo — por eso no hace falta escribir ningún width explícito.

    Para centrarla: cuando la card no ocupa el 100% del padre, hay espacio libre a sus lados. margin: auto en los laterales reparte ese espacio libre igual a izquierda y derecha. Si la card ocupara el 100%, no habría espacio libre que repartir y el centrado no tendría ningún efecto.

    Tu tarea
    1. En .card, escribe la propiedad que limita el ancho máximo a 300px (no es width).
    2. En .card, escribe la propiedad y el valor de margin que centra la card horizontalmente de forma automática.
    3. Comprueba en el navegador: la card debe estar centrada y, al estrechar la ventana por debajo de 300px, debe adaptarse en lugar de salirse.
    .pagina { min-height: 100vh; background: var(--color-bg); padding: var(--space-12) var(--space-4); } .card { /* ← escribe aquí la propiedad que limita el ancho máximo a 300px */ /* ← escribe aquí la propiedad que centra la card horizontalmente */ background: var(--color-surface); border-radius: var(--radius-lg); overflow: hidden; box-shadow: var(--shadow-md); position: relative; }
    🔍
    Comprueba overflow: hidden tú mismo Con el CSS del paso anterior activo, quita overflow: hidden de .card y mira las esquinas superiores de la imagen: la imagen sobresale por encima del border-radius. Esto ocurre porque border-radius solo redondea el contorno del contenedor, pero no recorta lo que hay dentro. overflow: hidden hace ese recorte. Vuelve a ponerlo cuando termines de comprobar.
  3. Estiliza la imagen

    La imagen ahora mismo tiene su tamaño original (600×400px): desborda la card por los lados y empuja el contenido hacia abajo. Al poner width: 100% y height: 180px a la vez, la imagen se estirará o comprimirá porque sus proporciones originales no coinciden con esa relación de aspecto. Hay una propiedad CSS que recorta la imagen para que rellene el espacio sin deformarse —como el modo «rellenar» de cualquier editor de fotos.

    Tu tarea
    1. En .card__imagen, escribe display: block, width: 100% y height: 180px.
    2. Añade la propiedad que evita que la imagen se deforme al tener ancho y alto fijos distintos de sus proporciones originales.
    3. Comprueba: la imagen debe ocupar exactamente el ancho de la card, medir 180px de alto y no deformarse. Las esquinas deben respetar el border-radius de la card — si no lo hacen, revisa overflow: hidden del paso anterior.
    .card__imagen { display: block; /* ya lo hereda del reset, pero lo explicitamos */ width: 100%; height: 180px; /* ← escribe aquí la propiedad que evita que la imagen se deforme */ }
    💡
    La imagen no necesita un div envolvente En este HTML la imagen es hija directa de article.card, sin ningún <div> intermedio. El overflow: hidden y el position: relative ya están en la card — no hace falta un contenedor extra. Añadir divs «por si acaso» es uno de los errores más comunes: cada elemento extra tiene un coste sin aportar nada.
  4. Posiciona el badge «Nuevo»

    Ahora mismo el badge aparece en el flujo normal: ocupa su propio espacio y empuja hacia abajo lo que viene después. Necesita estar flotando encima de la imagen, en la esquina superior derecha, sin ocupar espacio en el flujo normal del documento. Para eso existe position: absolute: saca el elemento del flujo y lo coloca en coordenadas exactas relativas a su ancestro posicionado más cercano. Ese ancestro es article.card, que ya tiene position: relative desde el paso 2 — sin eso, el badge se posicionaría respecto a la página entera.

    Tu tarea
    1. En .card__badge, escribe position: absolute.
    2. Añade top: 12px y right: 12px para situarlo en la esquina superior derecha.
    3. Comprueba: el badge debe aparecer sobre la imagen sin desplazar ningún otro elemento. Si se posiciona respecto a la página en lugar de a la card, revisa que .card tenga position: relative.
    .card__badge { /* ← valor de position que saca el elemento del flujo */ /* ← 12px desde arriba */ /* ← 12px desde la derecha */ background: var(--color-accent); color: var(--color-ink); font-size: var(--text-xs); font-weight: 700; font-family: var(--font-body); padding: 4px 12px; border-radius: var(--radius-full); letter-spacing: 0.04em; }
    🧠
    ¿Por qué el badge se posiciona respecto a la card y no a la página? Cuando un elemento tiene position: absolute, el navegador busca hacia arriba en el árbol HTML hasta encontrar el primer ancestro que tenga position distinto de static (el valor por defecto). Ese ancestro es su referencia de coordenadas. Si ningún ancestro estuviera posicionado, el badge se situaría respecto a la página entera — que no es lo que queremos. Por eso pusimos position: relative en la card en el paso 2.
  5. Estiliza el cuerpo de la card con nesting CSS

    Ahora el contenido del cuerpo aparece sin estilo: texto negro en Times New Roman, sin espaciado, sin jerarquía tipográfica. Tienes que aplicar los estilos de la guía de estilos a cada elemento. Escríbelos con nesting CSS: en lugar de un bloque separado por cada clase, todos van anidados dentro del bloque .card { } que ya tienes del paso 2.

    Los badges de alérgenos son <li>, que por defecto son bloques y se apilan verticalmente. Para que queden en fila necesitan un display que los haga comportarse como elementos de línea pero que respete su padding y borde — no es inline puro, sino una variante de él.

    El separador horizontal entre descripción y pie no es un elemento HTML: es un border-top en .card__pie. El pie pone precio y botón uno a cada lado usando display: flex con la propiedad que empuja los ítems a los extremos.

    Tu tarea — solo estas propiedades las escribes tú
    1. En .card__alergen: escribe el valor de display que pone los badges en fila respetando su padding y borde (no es inline ni block).
    2. En .card__pie: el pie ya tiene display: flex — añade la propiedad que empuja el precio al extremo izquierdo y el botón al extremo derecho.
    3. En .card__boton: abre la guía de estilos de HANA, ve a la sección «Botones» y copia las propiedades de la variante btn-primary en tamaño base. Los estados :hover y :focus-visible ya están dados — escribe las propiedades base del botón encima de ellos.
    .card { /* ... propiedades de los pasos anteriores ... */ .card__imagen { /* mueve aquí el bloque completo del paso 3 */ } .card__cuerpo { padding: var(--space-5); /* 20px interior por los cuatro lados */ } .card__categoria { font-size: var(--text-xs); /* 12px — el más pequeño de la escala */ font-weight: 600; letter-spacing: 0.1em; /* separa letras un 10% del tamaño de fuente */ text-transform: uppercase; /* todo en mayúsculas */ color: var(--color-brand); margin-bottom: var(--space-2); /* 8px de separación hacia abajo */ } .card__titulo { font-family: var(--font-display); /* Playfair Display — fuente editorial */ font-size: var(--text-xl); /* 20px */ font-weight: 600; color: var(--color-ink); line-height: var(--lh-snug); /* 1.4 — más compacto que el cuerpo */ margin-bottom: var(--space-2); } .card__descripcion { font-size: var(--text-sm); /* 14px */ color: var(--color-muted); /* gris medio — jerarquía visual */ line-height: var(--lh-body); /* 1.7 — cómodo para leer */ margin-bottom: var(--space-3); } .card__alergenos { list-style: none; /* quita los puntos de lista */ margin-bottom: var(--space-4); } .card__alergen { /* ← TÚ: display que los pone en fila respetando padding y borde */ font-size: 0.65rem; font-weight: 600; letter-spacing: 0.06em; /* separa letras un 6% */ text-transform: uppercase; padding: 2px 8px; /* 2px arriba/abajo, 8px izq/dcha */ border-radius: var(--radius-full);/* píldora — radio máximo */ border: 1px solid; /* el color lo pone la variante */ margin-right: var(--space-2); /* 8px entre badges */ } .card__alergen--pescado { color: hsl(210 70% 40%); /* azul oscuro */ border-color: hsl(210 70% 70%); /* azul medio */ background: hsl(210 70% 96%); /* azul muy claro */ } .card__alergen--sesamo { color: hsl(30 70% 40%); /* naranja oscuro */ border-color: hsl(30 70% 70%); /* naranja medio */ background: hsl(30 70% 96%); /* naranja muy claro */ } .card__pie { display: flex; /* ← TÚ: propiedad que empuja precio y botón a los extremos */ align-items: center; /* alinea precio y botón en el centro vertical */ padding-top: var(--space-3); /* 12px sobre el separador */ border-top: 1px solid var(--color-border); /* línea separadora sin HTML extra */ } .card__precio { font-family: var(--font-display); /* Playfair — mismo que el título */ font-size: var(--text-2xl); /* 24px — destaca sobre el resto */ font-weight: 700; color: var(--color-brand); } .card__boton { /* ← TÚ: copia aquí las propiedades de btn-primary (tamaño base) de la sección «Botones» de la guía de estilos de HANA */ &:hover { background: var(--color-brand-dark); /* oscurece al pasar el cursor */ border-color: var(--color-brand-dark); } &:focus-visible { outline: 3px solid var(--color-brand); /* anillo de foco para teclado */ outline-offset: 3px; /* separación del borde del botón */ } } }
  6. Añade el hover de elevación a la card

    Cuando el cursor pasa sobre la card, tiene que parecer que se eleva: la sombra crece y la card sube visualmente unos píxeles. Para el movimiento hacia arriba no uses margin-top: cambiar márgenes obliga al navegador a recalcular el flujo de toda la página y provoca saltos bruscos. transform: translateY() con un valor negativo mueve visualmente el elemento sin tocar el flujo, lo que permite una animación fluida. La transición debe declararse en el estado normal de la card, no en el :hover, para que también sea suave al salir del hover.

    Tu tarea
    1. En el bloque .card { }, añade transition para animar transform y box-shadow usando var(--transition-base).
    2. Justo debajo, anida &:hover { } con transform: translateY(-2px) y box-shadow: var(--shadow-lg).
    3. Comprueba: al pasar el cursor la elevación y la sombra deben cambiar de forma suave, no de golpe.
    .card { /* propiedades anteriores... */ transition: transform var(--transition-base), box-shadow var(--transition-base); &:hover { transform: translateY(-2px); box-shadow: var(--shadow-lg); } }
  7. Verifica el resultado con DevTools

    Haz clic derecho sobre cualquier parte de la card → Inspeccionar. Antes de dar la práctica por terminada, comprueba uno a uno estos puntos. Si algo no cuadra, el panel de estilos y el diagrama de caja de DevTools te dicen exactamente qué regla está aplicando el navegador y por qué.

    Lista de verificación
    • El padding de .card__cuerpo es 20px por los cuatro lados — no solo arriba. Compruébalo en el diagrama de caja de DevTools.
    • La imagen mide exactamente 180px de alto y no desborda las esquinas de la card.
    • Al inspeccionar el badge, el panel de estilos muestra position: absolute y las coordenadas top y right.
    • Ningún elemento hijo tiene un width fijo innecesario. El ancho de cada elemento debe venir de su contenedor, no de un valor explícito.
    • Navega con la tecla Tab hasta el botón «Añadir» — debe aparecer un anillo de foco visible sin usar el ratón.
    • Pasa el cursor sobre la card — la sombra y la elevación cambian de forma suave, no instantáneamente.
    • Compara tu resultado con la maqueta de referencia al principio de la práctica. Las proporciones, colores y tipografía deben coincidir.
