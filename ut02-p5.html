Situación

El equipo de HANA quiere añadir un formulario de reserva de mesa online. Tú te encargas del CSS: has de conseguir que los campos respondan visualmente a la interacción del usuario (foco, error, campo vacío obligatorio) sin JavaScript, usando solo pseudoclases y pseudoelementos de CSS.

ℹ️
Concepto clave: CSS tiene pseudoclases que reflejan el estado del formulario en tiempo real. :focus-visible muestra el foco al navegar con teclado. :required selecciona campos marcados obligatorios. :user-invalid muestra error solo tras interacción. :has() cambia el padre según su contenido.

Concepto: :focus vs :focus-visible

⚠️
El problema con :focus: Si usas :focus para mostrar el anillo de teclado, también aparece al hacer clic con ratón, lo que no es conveniente en botones y muchos controles. :focus-visible solo activa el estilo cuando el navegador detecta que el usuario navega por teclado.

Con ratón → sin anillo

/* :focus-visible no activa */

outline: none permanece

Con teclado (Tab) → anillo visible

/* :focus-visible activa */

outline: 3px solid var(--brand)

Pseudoclases de formulario — referencia rápida

Pseudoclase / pseudoelemento Cuándo aplica Uso típico en formularios
:focus-visible El elemento tiene foco y se llegó a él por teclado Anillo de foco visible solo al tabular
:required El campo tiene el atributo required Indicador visual de campo obligatorio
:optional El campo no tiene required Estilo distinto para opcionales
:valid El valor pasa la validación HTML (siempre, incluso vacío no requerido) Checkmark verde (con cautela)
:invalid El valor no pasa validación HTML (activa desde el primer render) ❌ No usarlo solo — aplica incluso antes de que el usuario toque el campo
:user-invalid Como :invalid pero solo tras interacción (blur o submit) ✅ Estado de error real: borde rojo, mensaje de ayuda
:placeholder-shown El placeholder del campo es visible (campo vacío) Saber si el usuario ha escrito algo
:has() El elemento contiene un descendiente que cumple la condición Colorear el label si su input hijo tiene :user-invalid
::placeholder — Color y estilo del texto de sugerencia
[type="email"] Selector de atributo: elemento con atributo type = "email" Distinguir tipos de input sin añadir clases

1 Estructura y tipografía de la sección

La sección de reserva tiene fondo neutro y el formulario en sí aparece sobre una tarjeta blanca centrada, con una anchura máxima de 560px para que los campos no se estiren demasiado en pantallas anchas.

.reserva { padding: var(--space-10) 0; /* relleno vertical */ background: var(--color-bg); } .reserva__contenedor { max-width: 560px; margin: 0 auto; /* centrado horizontal */ padding: 0 var(--space-6); } .reserva__form { background: var(--color-surface); border-radius: var(--radius-lg); padding: var(--space-8); box-shadow: var(--shadow-md); }

Tu tarea

  • Añade .reserva__titulo con font-family: var(--font-display), tamaño var(--text-2xl) y peso 700.
  • Añade .reserva__subtitulo con color var(--color-ink-muted) y tamaño var(--text-sm).
2 Estructura del campo y el label

Cada campo se envuelve en div.campo, que agrupa el label y el input. La posición relative en .campo será necesaria en el paso 5 para colocar el mensaje de error con ::after.

.campo { display: flex; flex-direction: column; /* label encima, input debajo */ gap: var(--space-1); margin-bottom: var(--space-5); position: relative; /* anclaje para ::after */ } .campo__label { font-size: var(--text-sm); font-weight: 500; color: var(--color-ink-muted); }

Tu tarea

  • Los campos :required deben tener el label con un asterisco rojo * al final. Añade esto con .campo:has(:required) .campo__label::after, usando content: ' *' y color: var(--color-brand).
3 Estilo base del input y ::placeholder

La clase .campo__input se aplica tanto a input como a select y textarea, así que el estilo base cubre los tres elementos. El placeholder tiene un color más suave que el texto real.

.campo__input { width: 100%; padding: var(--space-3) var(--space-4); border: 1px solid var(--color-border); border-radius: var(--radius-sm); font-family: var(--font-body); font-size: var(--text-base); color: var(--color-ink); background: var(--color-surface); transition: border-color 0.15s, box-shadow 0.15s; /* elimina el outline nativo — lo repondremos con :focus-visible */ outline: none; /* texto de sugerencia atenuado */ &::placeholder { color: hsl(40 10% 68%); /* más claro que el texto real */ font-style: italic; } }

Tu tarea

  • Añade el estilo para [type="date"] y [type="time"]: solo necesitan cursor: pointer para indicar que son interactivos.
  • Añade estilos para textarea.campo__input: resize: vertical (solo redimensionable en alto) y min-height: 5rem.
4 Foco con :focus-visible

Al tabular con el teclado, el campo activo muestra un anillo de foco azul rojizo (el color de marca de HANA). El borde también cambia para reforzar el estado.

.campo__input { /* … base del paso 3 … */ &:focus-visible { border-color: var(--color-brand); box-shadow: 0 0 0 3px hsl(0 70% 35% / 0.15); /* halo de 3px, 15% de opacidad */ } }

Tu tarea

  • Copia el bloque de arriba dentro del selector .campo__input usando CSS nesting.
  • Prueba en el navegador: usa la tecla Tab para moverte entre campos — ¿aparece el anillo? ¿desaparece al hacer clic con el ratón?
5 Estado de error con :user-invalid y ::after

Cuando el usuario introduce un valor incorrecto en un campo y mueve el foco fuera (blur), :user-invalid se activa. Usamos ::after en el .campo padre para inyectar un mensaje de error sin tocar el HTML. El texto del mensaje viene del atributo data-error del input.

💡
Truco: content: attr(data-error) lee el valor de cualquier atributo HTML y lo inserta como texto en el pseudoelemento. Así podemos personalizar el mensaje por campo desde el HTML.
.campo__input { /* … pasos anteriores … */ &:user-invalid { border-color: var(--color-error); /* borde rojo */ background: var(--color-error-lt); /* fondo rosa muy suave */ } } /* mensaje de error debajo del input */ .campo:has(.campo__input:user-invalid)::after { content: attr(data-error); /* lee el atributo data-error del .campo */ display: block; font-size: var(--text-xs); color: var(--color-error); margin-top: var(--space-1); }

Tu tarea

  • Añade data-error="Introduce un correo válido" al div.campo que contiene el input de email.
  • Añade data-error="Este campo es obligatorio" al div.campo que contiene el input de nombre.
  • Escribe el CSS del bloque de arriba (dentro del selector .campo__input con nesting para :user-invalid, y el selector .campo:has(…)::after fuera).
  • Prueba: escribe un correo malformado en el campo email y haz clic fuera. ¿Aparece el mensaje?
6 Botón de envío con :focus-visible

El botón .btn-primary ya tiene estilos de la P1. Añade únicamente el estado de foco por teclado y asegúrate de que ocupe todo el ancho disponible en el formulario.

.reserva__form { .btn-primary { width: 100%; /* ancho completo dentro del form */ margin-top: var(--space-2); &:focus-visible { outline: 3px solid var(--color-brand); outline-offset: 3px; } } }

Tu tarea

  • Escribe el CSS del bloque de arriba con CSS nesting (el botón anidado dentro del form).
  • Verifica con Tab que el botón recibe foco visible y que al hacer clic no muestra el outline.
